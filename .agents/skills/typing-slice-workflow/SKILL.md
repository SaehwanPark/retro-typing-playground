# 기능 슬라이스 진행

이 스킬은 사용자에게 전달할 기능을 구현하거나 진행 중인 기능 작업을 이어받을 때 사용한다. 단순 문구 수정은 저장소 공통 지침으로 처리한다.

## 필요한 입력

- 작업 요청, 현재 브랜치와 작업 트리 상태, 대상 항목이 적힌 `docs/SPEC.md`.
- 사용자 동작과 제약의 근거가 되는 `docs/PROJECT-SPEC.md`.
- 이어받는 작업이면 해당 PR과 검증 결과.

## 진행 순서

1. 요청에 지정한 슬라이스 또는 [바로 다음에 구현해야 함] 항목을 고른다. 현재 상태와 완료를 판단할 사용자 행동을 확인하고, 계획이 바뀌면 제품 명세와 체크리스트를 함께 수정한다.
2. 기존에 해당 슬라이스를 담은 브랜치와 PR이 있으면 이어서 쓴다. 새 작업은 최신 `main`을 기준으로 임시 브랜치를 만든다. 첫 커밋에서 체크리스트 항목을 진행 중으로 옮기고 [바로 다음에 구현해야 함]을 [지금 구현중]으로 바꾼다. 첫 커밋을 푸시한 뒤 `main` 대상 Draft PR을 열고 대상 항목, 범위, 완료 조건을 적는다.
3. 동작 단위로 커밋하고 같은 브랜치에 푸시한다. 입력·채점·세션·저장 규칙을 바꿀 때는 [typing-domain](../typing-domain/SKILL.md)의 확인 절차를 적용한다. 코드베이스와 런타임 동작에 변화가 없으면 테스트나 CI를 실행하지 않는다. CI를 설정할 때도 이 변경에서는 테스트 잡이 시작되지 않도록 구성한다.
4. 완료 조건을 충족하면 항목을 체크해 완료로 옮긴다. 진행 레이블을 제거하고 다음 항목에 [바로 다음에 구현해야 함]을 붙인다. 사용자 동작과 경계가 바뀌었으면 프로젝트 명세를, 실행법이나 지원 범위가 바뀌었으면 README를 수정한다. 실제 확인한 범위와 남은 사항을 PR에 기록한다.
5. 최종 커밋을 푸시하고 PR을 준비 상태로 바꾼다. 필요한 리뷰와 저장소 머지 조건을 충족하면 `main`에 머지한다. 머지를 확인한 뒤 작업에 사용한 임시 로컬·원격 브랜치를 삭제한다.

## 버전

공백 저장소는 `v0.0.0`이다. 완료한 작은 사용자 기능마다 마지막 자리를 올린다. 기능이 쌓여 최종 사용자의 경험이 상당히 바뀌면 두 번째 자리를 올리고 마지막 자리를 0으로 되돌린다. 메이저 릴리스에서는 첫 자리를 올리고 뒤의 두 자리를 0으로 되돌린다. 문서만 바뀌면 버전을 유지한다. 버전이 바뀌는 슬라이스에서는 체크리스트와 앱 메타데이터의 버전을 맞춘다.

## 인계와 확인

`docs/SPEC.md`에 상태를, PR에 커밋과 확인 결과를 남긴다. 머지가 막히면 PR과 브랜치를 유지하고 재개에 필요한 조건을 기록한다. 예를 들어 실제 한글 IME에서 제출 동작을 확인하지 못했다면 해당 기준을 미완료로 남기고 필요한 OS·브라우저 조합을 PR에 적는다. 머지 후에는 버전, 체크리스트, 프로젝트 명세, README의 설명이 같은 동작을 가리키는지 확인한다.
