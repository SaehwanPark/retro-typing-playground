# 타자 연습 도메인

입력과 결과 사이의 규칙을 바꾸는 작업에 사용한다. PR 상태와 버전은 [typing-slice-workflow](../typing-slice-workflow/SKILL.md)를 따른다.

## 필요한 입력

- `docs/PROJECT-SPEC.md`의 사용자 동작과 제약, `docs/SPEC.md`의 대상 슬라이스.
- 관련 세션 타입, 입력 처리, 콘텐츠 또는 저장 스키마가 이미 있으면 현재 코드와 재현 절차.

## 작업 순서

1. 적용 모드, 유효한 시작 상태, 받아들일 이벤트와 관찰할 결과를 정한다. 예를 들어 단문에서 조합 확정에 쓴 Enter는 입력을 확정하고 다음 Enter가 제시문을 제출한다.
2. 연습의 제약을 데이터와 상태 타입에 반영한다. 점수와 상태 전이 함수에 확정 입력과 시각을 값으로 넘겨 같은 입력에서 같은 결과를 얻는다. 화면 갱신, 초점 이동, 시계와 기록 저장은 도메인 밖에서 처리한다.
3. 한글 입력을 건드리면 조합 중 표시와 확정된 값을 나눈다. 이벤트 순서가 달라져도 같은 입력이 두 번 채점되지 않는지, NFC 정규화와 문자소 단위 비교로 오타 위치와 길이가 일치하는지 확인한다.
4. 채점을 건드리면 정상 완료와 오타·수정·공백·초과 입력을 확인한다. 저장을 건드리면 새로고침, 손상된 스키마, 중복 완료, 저장 실패 뒤에도 연습을 계속할 수 있는지 확인한다.
5. 도메인 변경은 관련 순수 함수 검증과 화면 경계의 확인 결과를 남긴다. IME 동작을 바꿨으면 실제 OS의 한국어 입력기에서 확인한 환경과 아직 확인하지 못한 환경을 기록한다. 문서 작업에는 테스트·CI 대신 명세와 기록의 일관성을 확인한다.

## 산출물

작업 범위의 코드와 검증 근거를 슬라이스 PR에 담는다. 사용자 동작이나 불변식이 바뀌면 프로젝트 명세를 동기화한다. 예컨대 저장이 차단된 환경에서 결과 표시가 성공해도 저장 성공으로 기록하지 않는다.
