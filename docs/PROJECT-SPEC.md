# Retro Typing Playground 프로젝트 명세

한메타자교실을 기억하는 사람과 한글 타자를 처음 배우는 사람이, 현재 데스크톱 브라우저에서 키보드만으로 연습을 시작하고 결과를 확인할 수 있는 로컬 타자 연습 앱을 만든다. 구현 순서와 현재 상태는 [SPEC.md](SPEC.md)에서 확인한다.

## 참조 경험과 제품 범위

참조 서비스는 DOS·PC통신풍 화면에서 한 줄·짧은 글·긴 글 연습과 단어형 타자 게임을 제공한다. 소개 자료에는 방향키와 Enter로 메뉴 선택, Esc로 복귀, 입력 중 속도와 정확도 확인, 직전 문장과 속도 비교가 설명되어 있다. [온라인 타자교실](https://typing.zidell.me/) · [에듀베이지 소개](https://www.edubeige.com/post/typing-zidell)

가져올 경험은 메뉴에서 바로 연습을 고르고, 제시문과 입력을 비교하며, 기록을 본 뒤 곧바로 다시 연습하는 흐름이다. 자체 제목과 화면 구성을 사용한다. 짙은 배경에 호박색 강조색, 고정폭 계열 제목, 제시문과 입력창을 위아래로 둔 연습 카드로 터미널 분위기를 살린다. 예문과 게임 콘텐츠는 직접 작성하거나 사용 조건이 확인된 자료를 사용한다.

| 범위 | 사용자에게 보이는 동작 |
| --- | --- |
| 첫 슬라이스 | 로컬 주소를 열고 한글 단문 한 편을 연습한다. 입력 중 오타, 정확도, 분당 글자 수를 확인하고 완료 후 최종 결과를 본다. 같은 문장을 다시 연습하거나 메뉴로 돌아간다. |
| 초기 제품 | 한글 자리·낱말·단문·장문 연습을 제공한다. 영문은 낱말·단문부터 추가한다. 같은 브라우저에서 최근 결과와 설정을 이어서 본다. |
| 후속 범위 | 독자적인 시간 제한 타자 도전 모드를 제공한다. 설치형 패키지와 다른 자판 배열은 실제 수요가 생길 때 검토한다. |

앱의 실행과 연습은 오프라인을 기본으로 한다. 계정, 서버 동기화, 공개 순위, 원격 측정, 외부 폰트와 CDN은 초기 범위에서 제외한다. 데스크톱과 물리 키보드를 우선한다.

## 화면과 사용 흐름

| 화면 | 사용자 동작과 피드백 |
| --- | --- |
| 시작 메뉴 | 제공 중인 연습을 마우스로 고를 수 있다. 메뉴 안에서는 위·아래 방향키 또는 Tab과 Shift+Tab으로 이동하고 Enter로 선택한다. |
| 연습 | 선택 직후 이름이 있는 입력창에 초점을 둔다. 제시문, 현재 위치, 오타를 보여주고 확정 입력이 바뀔 때 정확도와 분당 글자 수를 갱신한다. 정확·오타는 색과 별도의 밑줄 또는 표시로 구분한다. 뒤로 가기 버튼과, 조합 중이 아닐 때의 Esc로 메뉴에 돌아간다. |
| 결과 | 완료 요약에 초점을 옮긴다. 정확도, 분당 글자 수, 경과 시간과 함께 다시 연습, 메뉴로 돌아가기 버튼을 제공한다. 메뉴로 돌아오면 직전에 선택한 항목에 초점을 둔다. |
| 기록과 설정 | 최근 완료 결과를 모드별로 확인한다. 결과 화면에서 같은 모드와 언어의 직전 기록과 비교한다. 글자 크기를 바꾸고 로컬 데이터를 지울 수 있다. 저장에 문제가 생기면 화면에 상태를 표시하며 연습은 계속된다. |

브라우저 확대 200%에서 제시문, 입력창, 주요 버튼을 모두 사용할 수 있어야 한다. 텍스트와 초점 표시를 읽기 쉽게 만들고, 자주 바뀌는 입력 상태와 별도로 완료·저장 상태를 보조 기술에 알린다. 앱의 단축 동작은 관련 메뉴나 입력 영역에 한정하며 IME와 브라우저 기본 조작을 보존한다.

### 명세를 구체화한 초기 가정

- 기본 인터페이스 언어는 한국어이고 한글 단문 첫 예시는 2벌식 입력을 상정한다. 번역 지원은 A01에 필요하지 않다.
- 첫 단문은 직접 작성한 저작권 부담 없는 문장으로 번들에 담는다. 60자 이내로 정하고, 입력 부담을 낮추면서 띄어쓰기와 문장 부호를 포함한 연습을 보여주기 위함이다.
- 한글 입력에서 Enter는 먼저 조합을 확정하고 다시 눌러야 제출할 수 있다. IME의 이벤트 순서가 브라우저에 따라 다른 경우를 검증하고, 일반 영문 입력기의 Enter는 한 번으로 제출할 수 있게 한다.
- 로컬 실행을 위한 Node.js 기준선은 Vite가 지원하는 Node 22.12.0 이상으로 시작하고, 검증 시점의 지원 LTS를 선택한다. 빌드 및 개발에는 npm 잠금 파일의 버전을 쓰고, 사용자 실행에는 의존성 설치를 요구하지 않는다.
- 입력 시간은 첫 확정 글자 입력부터 제출까지로 측정한다. 분당 글자 수의 초기 피드백은 1초 미만에서 `—`로 두고, 필요하면 짧은 연습 세션에서의 실제 사용 근거로 조정한다.
- 최신 데스크톱 브라우저의 텍스트 입력을 목표로 한다. 모바일 터치 자판, 오프라인 브라우저 캐시(Service Worker), 설치형 앱 패키징은 A01에 포함하지 않는다.

## 실행과 기술 선택

Windows 11, macOS, Linux에서 동일한 정적 웹앱을 실행한다. 로컬 배포물에는 빌드한 `dist/`와 Node.js 내장 HTTP·파일 모듈을 쓰는 `serve.mjs`를 함께 둔다. 지원되는 Node.js LTS를 설치한 컴퓨터에서 `node serve.mjs`로 시작하고 브라우저에서 `http://127.0.0.1:4173/`를 연다. 실행기는 해당 루프백 주소에만 바인딩하고 `dist/` 안의 정적 파일만 제공한다. 포트 사용 중이면 원인을 안내하고 종료한다. 고정 주소를 사용하면 브라우저의 저장 공간을 일관되게 사용할 수 있다. Node.js 준비 이후에는 추가 패키지 설치나 인터넷 연결 없이 실행한다.

| 선택 | 이유 |
| --- | --- |
| 브라우저 웹앱 | 세 OS에서 하나의 배포물을 쓰고, 운영체제와 브라우저가 제공하는 한글 입력기를 이용한다. 운영체제별 데스크톱 패키징은 후속 선택지로 둔다. |
| TypeScript strict + React + CSS | 모드·세션 상태를 타입으로 제한하고, 순수 상태 전이의 결과를 화면에 표시한다. 스타일과 입력에는 브라우저 기본 기능을 우선한다. [React의 useReducer](https://react.dev/reference/react/useReducer) |
| Vite + npm | 개발 서버와 정적 빌드를 같은 프로젝트에서 관리한다. 버전 요구사항, 잠금 파일, 공통 명령은 첫 구현에서 확정한다. [Vite 정적 빌드](https://vite.dev/guide/build) |
| 브라우저 localStorage | 브라우저 프로필별 설정과 소량의 완료 기록을 저장한다. 저장소가 지워지면 기록도 초기화된다. [localStorage 동작](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage) |
| Vitest + Playwright | 순수 함수의 계산 경계와 브라우저에서의 대표 사용자 흐름을 각각 확인한다. 실제 한글 조합 동작은 OS별 수동 확인을 병행한다. [Vitest](https://vitest.dev/guide/) · [Playwright 브라우저 지원](https://playwright.dev/docs/browsers) |

## 구현 구조

아래 경로는 구현을 시작할 때 적용할 경계다. 기능이 들어오는 순서에 맞춰 디렉터리를 만든다.

| 위치 | 책임 |
| --- | --- |
| `src/domain/` | 연습 자료, 세션 타입, 상태 전이, 입력 비교와 점수 계산. 브라우저, React, 시스템 시각, 저장소를 직접 참조하지 않는다. |
| `src/app/` | 메뉴·연습·결과의 전환과 기능 연결. 타입이 지정된 이벤트를 도메인에 넘기고 초점 이동·결과 저장을 실행한다. |
| `src/ui/` | React 화면과 접근 가능한 폼, 한글 입력을 받는 브라우저 어댑터, 결과 표시. |
| `src/storage/` | 로컬 데이터 읽기·검증·변환·저장. |
| `src/content/` | 안정적인 ID, 언어, 모드, 제시문, 출처를 담은 번들 콘텐츠. |

`키보드·IME → 확정된 입력과 경과 시각 → 순수 상태 전이 → 화면 갱신 → 완료 결과 저장`

- `Lesson`은 모드 식별자로 구분한다. 자리 연습은 물리 키 목록, 단문과 낱말은 하나의 제시문, 장문은 짧은 줄 목록을 담는다. 빈 목록과 빈 제시문은 콘텐츠를 읽을 때 거른다. 자리 연습은 대상 위치와 `KeyboardEvent.code`를 비교한다. 입력된 글자 대신 키 위치를 배우기 위한 모드이며 키 길게 누르기와 브라우저 단축키는 시도로 집계하지 않는다.
- 화면 상태는 메뉴, 연습, 결과 중 하나다. 연습은 확정 텍스트가 비어 있는 시작 전 상태와 시작 시각이 있는 진행 상태를 구분한다. 재시도는 입력·계수·시각이 빈 새 세션을 열고, 결과에는 완료한 세션의 집계만 담는다.
- 운영체제의 IME가 조합 중인 텍스트는 편집기에 남긴다. 조합이 끝난 실제 입력값을 한 번만 반영하고, 조합 확정에 사용한 Enter를 제출로 처리하지 않는다. 확정 버퍼를 NFC로 정규화하고 `Intl.Segmenter`의 문자소 단위로 비교하므로 완성형과 분해형 한글을 같은 글자로 처리한다. [조합 종료 이벤트](https://developer.mozilla.org/en-US/docs/Web/API/Element/compositionend_event) · [문자소 분할](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/Segmenter)
- 입력은 일반 편집과 Backspace를 지원한다. 붙여넣기와 끌어놓기는 연습 입력창에서 차단하고 이유를 표시한다. 제시문과 같은 길이 이상 입력하면 오타가 남아 있어도 Enter로 완료할 수 있어서, 결과에서 정확도를 확인하고 다시 연습할 수 있다. 짧으면 입력을 보존하고 남은 길이를 안내한다. 장문은 같은 방식으로 줄을 확정하며, 마지막 줄에서 세션을 완료한다.

### 점수 규칙

- 확정 입력을 위치별로 제시문과 비교한다. 정확도는 일치한 글자 수를 전체 입력 글자 수로 나눈 백분율이다. 초과 글자는 오타로 센다. 완료 전에 수정한 오타는 최종 정확도에 반영되지 않는다.
- 분당 글자 수는 일치한 최종 입력 글자 수 × 60 ÷ 경과 초다. 공백과 문장부호도 제시문과 일치하면 한 글자로 센다. 물리 타건 수와 혼동을 피하도록 화면에 `글자/분`으로 표시한다. 첫 확정 입력에서 시작해 제출 동작에서 멈추며, 장문은 줄 사이 시간과 입력을 모두 포함한다. 1초 미만은 `—`로 표시하고 분모가 비어 있는 경우에는 점수를 표시하지 않는다. 계산은 원래 정밀도를 유지하고 화면에서 정수로 반올림한다.
- 시간 경과는 화면 경계에서 `performance.now()`로 읽어 이벤트에 담는다. 완료 후 결과는 고정되며, 장문에서는 먼저 확정한 줄을 다시 채점하지 않는다.
- 자리 연습은 올바른 키를 누르면 다음 위치로 넘어간다. 결과는 경과 시간과 올바른 시도를 전체 시도로 나눈 정확도를 보여준다.

### 로컬 기록과 실패 처리

고정 주소의 저장 데이터에 스키마 버전을 붙인다. 설정과 완료 기록은 별도의 키에 둔다. 기록은 고유한 세션 ID로 중복을 피하며 최근 100회만 보존한다. 각 기록에는 세션·자료 ID, 완료 시각, 모드와 언어, 소요 시간과 점수만 담는다. 입력 원문은 세션이 끝날 때 폐기한다.

여러 탭에서 동시에 완료해도 기록이 유실되지 않도록 저장 어댑터는 Web Locks로 읽기·수정·쓰기와 초기화를 직렬화한다. 잠금을 사용할 수 없으면 저장 실패와 같은 방식으로 안내한다. [Web Locks API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API)

잘못된 데이터나 지원하지 않는 버전을 읽으면 기본 설정과 세션 메모리로 연습을 유지하고 원본 저장값을 보존한다. 쓰기에 실패하면 현재 결과를 보여주고 저장되지 않았음을 알린다. 사용자가 로컬 데이터 삭제를 명시적으로 선택하면 초기화할 수 있다.

## 품질 기준

- 새 브라우저 프로필에서 외부 네트워크를 끊고 로컬 주소의 첫 로드, 연습, 결과, 재시도를 완료한다. 기록 기능이 들어오면 같은 주소로 다시 열었을 때 완료 기록이 보존되는지 확인한다.
- 지원 확인의 기준은 Windows 11의 Edge와 Microsoft 한국어 IME, macOS의 Safari와 한국어 두벌식, Linux의 Firefox와 IBus 기반 두벌식이다. 세 환경에서 조합 중 오타 미표시, Backspace, 확정용 Enter와 제출용 Enter의 구분, 키보드로 메뉴 복귀를 확인한다. Chromium·Firefox·WebKit 자동 확인은 실제 OS 입력기 확인을 보완한다.
- 자동 검증은 실제 코드 또는 런타임 동작이 바뀌는 슬라이스에 한해 변경에 맞춰 실행한다. 문서 변경은 링크, 체크리스트, 구현 상태를 대조한다. 지원 선언은 실제 확인한 환경에 맞춘다.
